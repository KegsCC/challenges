# Challenges from 27th November 2026

The challenges this week are **related** to the process of [lexical analysis](https://en.wikipedia.org/wiki/Lexical_analysis),
which is the first step of making your own text-based programming language.

## Beginner challenge

Input a value from the user.

If it has any numbers in it, print `number`. Otherwise, it will be a word.
For each word, if it is fully lowercase, print `lowercase`. 
If it is fully uppercase, print `uppercase`.
If it has uppercase and lowercase letters, then print `mixcase`.

Expected input/output:

| input                                | output                               |
|--------------------------------------|--------------------------------------|
| 1000                                 | number                               |
| 1000abc                              | number                               |
| hello                                | lowercase                            |
| WORLD                                | uppercase                            |
| abcDEF                               | mixcase                              |
| King Edward                          | mixcase                              |
|                                      | lowercase                            |

Note: that last one is what you should get if the user inputs nothing (i.e. they press enter immediately).

## Intermediate challenge

Input a sentence from the user. Remove any non-alphabetic characters so the resulting text is only made up of letters *and spaces*.
Then split it by spaces. For each word in the resulting list, print it, and then print a colon, like demonstrated below.
Then, if it is fully lowercase, print `lowercase` on the same line.
Likewise, if it is fully uppercase, print `uppercase` instead. 
If the word is fully lowercase except the first letter which is uppercase, print `proper noun` instead.
Otherwise, the word is made of lowercase *and* uppercase characters, so print `mixcase` instead

example:

```
Enter a sentence: King Edward is the one who made KEGS.
King: Proper noun
Edward: Proper noun
is: lowercase
the: lowercase
one: lowercase
who: lowercase
made: lowercase
KEGS: uppercase
```

## Advanced challenge

In python, a *string literal* is the technical word for when you use quotes to enclose text, for example `"Hello world"` in `print("Hello world")`.

Write a program to check whether a user-inputted string would be a valid string literal.

Rules for string literals:

- A string literal must start with a quotation mark (`"`) and end with a quotation mark.
- Between the two quotation marks, any letters are allowed except for `"` and `\`, which are treated specially.
- If there is a backslash (`\`), then it will be skipped, but the next character will be "escaped".
  - If the escaped character is a `"`, then it will *not* end the string, but rather become a regular quote.
  - If the escaped character is a `\` itself, then it will not escape the character after it.
  - If the escaped character is an `n` or a `t`, these would designate newlines or tab characters, so they are valid.
  - If the escaped character is neither `"`, `\`, `n` or `t`, then the entire string literal should be considered as invalid.
 
Optional extension: 
support the single quote `'`. 
If the string starts with a single quote, then it must end with a single quote. 
Like double quotes, single quotes can be escaped.
Additionally, in single-quoted strings, double quotes `"` do not need to be escaped and vice versa.

Examples:


| input                                | output                               |
|--------------------------------------|--------------------------------------|
| "hello"                              | valid                                |
| asjdfkl                              | invalid (missing starting quote)     |
| "asdjf                               | invalid (missing ending quote)       |
| "hello world"                        | valid                                |
| "hello\nworld"                       | valid                                |
| "hello\tworld"                       | valid                                |
| "hello\"world\""                     | valid                                |
| "hello\"world\"                      | invalid (missing ending quote (because it is escaped)) |
| ""                                   | valid                                |
| "\""                                 | valid                                |
| "C:\\Windows\\System32\\"            | valid                                |
| "C:\Windows\System32\"               | invalid (`\W` is not a valid escape sequence) |
| "\\\\\\\\\\\\\"\\\"\t\nhello world"  | valid                                |

## Supreme challenge

Write a program to lex an arithmetic expression supporting `+`, `-`, `*`, `/`, *positive* integers, and `(` and `)`, ignoring any spaces.

Lex is just a technical name for *split into a list of words* (you can ignore the actual meaning of the operators and values). Examples are below.

Don't worry about if the expression actually makes mathematical sense. For example, `33 44` should still be lexed as `["33", "44"]`


| input                                | output                               |
|--------------------------------------|--------------------------------------|
| 3                                    | `["3"]`                              |
| 37                                   | `["37"]`                             |
| 1 + 2                                | `["1", "+", "2"]`                    |
| 12+34                                | `["12", "+", "34"]`                  |
| 12 * (34+56)                         | `["12", "*", "(", "34", "+", "56", ")"]` |
| 1----5                               | `["1", "-", "-", "-", "-", "5"]`     |
| 12 * 34 - 56 / 123 - 1               | `["12", "*", "34", "-", "56", "/", "123", "-", "1"]` |
| 3 4 5 +                              | `["3", "4", "5", "+"]`              |
| 12 * 34 - 56/123 //)*+- 1            | `["12", "*", "34", "-", "56", "/", "123", "/", "/", ")", "*", "+", "-", "1"]` |

## Champion challenge

In the supreme challenge, you were tasked with creating a lexer. A lexer is something which produces a list of *tokens* (technical name for a word).
You should also associate a *type* with each of the tokens. I.e., there should be a label which says whether the token is a plus, minus, divide, star, left bracket, right bracket, or number.

Since you are at the supreme challenge, clearly you are too good at this. Take a go at writing an actual *evaluator* for an arithmetic expression 
(without relying on the python interpreter with `eval` or similar).

Here are some possible ways you can do it:

- convert to postfix expression, then evaluate postfix expression: <https://www.geeksforgeeks.org/dsa/convert-infix-expression-to-postfix-expression/> (I think this is the [shunting yard algorithm](https://en.wikipedia.org/wiki/Shunting_yard_algorithm) which comes from Dijkstra)
- recursive descent parsing or pratt parsing: <https://matklad.github.io/2020/04/13/simple-but-powerful-pratt-parsing.html>
- parenthesisation: <https://en.wikipedia.org/wiki/Operator-precedence_parser#Alternative_methods>
